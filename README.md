# wg-v4-exit

**给纯 IPv6 服务器借一台双栈 VPS 做 IPv4 出口。**

纯 IPv6 的服务器越来越便宜，但很多网站、API 和软件源只有 IPv4，服务器自己搭的网站需要调用这些 v4 接口时直接 `Network is unreachable`。常见的解决办法是 Cloudflare WARP 一键脚本，但免费 WARP 是 Anycast 共享出口，IP 飘、节点挤、时不时掉线，跑生产网站不踏实。

wg-v4-exit 换个思路：**不用任何第三方出口，用你自己手里的另一台双栈 VPS 做出口。** 两台机器之间拉一条点对点的 WireGuard 隧道，纯 v6 机器只把 IPv4 流量送进隧道，从双栈机的 IPv4 地址出去。出口是你自己的机器，IP 固定、带宽独享、没人跟你抢节点，稳定性就是 WireGuard 本身的稳定性。

## 功能

- **交互面板，逐级填写**：运行脚本先选本机角色，再一步步填参数（每项都有智能默认值，网卡名、公网 IP 自动检测），填完有汇总页确认，确认后才动手改系统，最后输出一页完整的连接信息。
- **两种角色，一个脚本**：
- **出口机**（双栈 VPS）：WireGuard 服务端，自动开启 IPv4 转发和 NAT，自动生成密钥，装完输出公钥 + 公网 IPv6 + 端口，正好是应用机要填的三样。
- **应用机**（纯 IPv6 服务器）：WireGuard 客户端，`AllowedIPs = 0.0.0.0/0` 只接管 IPv4，**IPv6 默认路由完全不动**，SSH 和原生 v6 访问不受隧道影响；装完自动自检（隧道连通性、v4 出口、v6 出口）并输出本机公钥。
- **WARP 冲突检测**：应用机安装时自动检测残留的 WARP（它也会抢 IPv4 默认路由），提示一键卸载，避免两条默认路由打架。
- **密钥安全**：私钥在各自机器本地生成、只留在本地，两台机器之间只交换公钥，脚本和仓库里不出现任何私钥。重装自动复用旧密钥，另一端不用改配置。
- **保活**：客户端带 `PersistentKeepalive = 25`，NAT 映射不会过期，隧道长期不断。
- **管理菜单**：查看本机连接信息（公钥 / 公网 IP / 接口状态）、出口机补填或更新应用机公钥、一键卸载，都在同一个面板里。
- **MTU 默认 1380**：已按「IPv6 外层 + WireGuard 封装」的开销算好，避免大包黑洞导致的网页卡死。

## 拓扑

```
IPv6 直连（隧道外层）
应用机 ─────────────────────────────── 出口机（双栈 VPS）
（纯 IPv6） WireGuard 隧道 │ NAT
│ 内层只跑 IPv4 │
│ ▼
└── IPv6 流量：原生直出 IPv4 互联网（出口 IP = 出口机的 IPv4）
IPv4 流量：进隧道 ──────────────┘
```

## 准备

- 一台**双栈 VPS**做出口机（有公网 IPv4 + IPv6，Debian / Ubuntu）
- 一台**纯 IPv6 服务器**做应用机（Debian / Ubuntu）
- 出口机的商家面板 / 安全组放行一个 UDP 端口（默认 51820）的 **IPv6 入站**
- 两台都用 root 运行脚本

> 出口机最好选离应用机同机房 / 同地区的，隧道延迟最低。出口机的 IPv4 就是应用机最终的 v4 出口 IP，选之前想一下这个 IP 干不干净、带宽够不够。

## 使用方法

### 一键运行（两台机器上都是同一条命令）

```bash
wget -N https://raw.githubusercontent.com/emmaforge/wg-v4-exit/main/menu.sh && bash menu.sh
```

**首次运行后，脚本会把自己注册成系统指令 `v4exit`。** 之后在任意一台装过的机器上，终端直接输入：

```bash
v4exit
```

就能随时呼出面板，不用再记下载地址（补公钥、看状态、卸载都从这里进）。`v4exit server` / `v4exit client` / `v4exit info` / `v4exit peer` / `v4exit uninstall` 也可以直达对应功能。

打开面板后：

```
1. 本机是双栈 VPS —— 安装服务端 + NAT
2. 本机是纯 IPv6 服务器 —— 安装客户端，借 v4 出口
3. 查看本机连接信息（公钥 / 公网 IP / 接口状态）
4. 出口机补填 / 更新应用机公钥
5. 卸载
0. 退出
```

### 正确的安装顺序（三步）

WireGuard 两端要互填公钥，所以顺序是这样，不用一次填完：

**第一步，先装出口机。** 在双栈 VPS 上运行脚本选 `1`，逐级填写：出口网卡（自动检测）→ 监听端口（默认 51820）→ 隧道地址（默认 10.66.66.1/24）→ 应用机公钥（**先留空**）→ MTU（默认 1380）。确认后安装，结尾会输出一页信息，记下其中的**公网 IPv6、本机公钥、监听端口**。

**第二步，装应用机。** 在纯 IPv6 服务器上运行脚本选 `2`，把第一步记下的 IPv6、公钥、端口填进去，其余用默认值；中途如果检测到 WARP，按提示卸载。确认后安装，结尾输出**本机公钥**，记下来，同时看自检结果（此时隧道 ping 可能还不通，正常，因为出口机还没填你的公钥）。

**第三步，出口机补填公钥。** 回到出口机输入 `v4exit` 选 `4`，粘贴第二步的应用机公钥。隧道立即握手生效，不用重启任何一端。

### 验证（在应用机上）

```bash
ping -c3 10.66.66.1 # 隧道通
ping -c3 github.com # 只有 v4 的域名，现在能通了
curl -4 ip.sb # 显示出口机的 IPv4
curl -6 ip.sb # 显示应用机自己的原生 IPv6，没有被隧道抢走
wg show v4exit # 看 latest handshake 有时间、transfer 有流量
```

网站、Docker、apt、git 全部透明走这条 v4 出口，不需要给任何程序单独配代理。

## 命令行用法

不想进菜单也可以直接带参数：

```bash
bash menu.sh server # 直接进出口机安装向导
bash menu.sh client # 直接进应用机安装向导
bash menu.sh info # 查看本机连接信息
bash menu.sh peer # 出口机补填 / 更新应用机公钥
bash menu.sh uninstall # 卸载
bash menu.sh --dry-run # 演示模式：走完面板流程，只把配置写到./dryrun-output/，不改系统
```

## 常见问题

**应用机 ping 不通出口机隧道地址（10.66.66.1）**
先看 `wg show v4exit`：没有 handshake，多半是出口机还没补填应用机公钥（做完第三步），或者出口机安全组没放行 UDP 端口的 IPv6 入站；有 handshake 但 ping 不通，去出口机检查 NAT 规则在不在：`iptables -t nat -L POSTROUTING`。

**能打开网页但大文件 / 大网页卡死**
MTU 黑洞。向导里 MTU 默认 1380 已经避开绝大多数情况，如果出口机本身还套着隧道（比如商家是 NAT 机），把两端的 MTU 一起改小到 1280 再试，两端要一致地改应用机侧即可（WireGuard 取两端较小值协商，改应用机一端最省事）。

**应用机装完后原来的 WARP 网站 / 程序出问题**
WARP 已按提示卸载，它的全局路由本来就和本隧道冲突。依赖 WARP 出口的程序改走新隧道即可，行为一致：系统级 IPv4 默认路由出站。

**想换出口机**
在新双栈机上装出口机（选 1），应用机重跑向导（选 2）填新出口机的 IPv6 和公钥即可；应用机密钥会自动复用，不想复用就先选 5 卸载干净再装。

**出口 IP 被目标网站风控**
出口 IP 就是出口机自己的 IPv4，干不干净取决于那台机。换一台双栈机做出口即可，步骤同上。

**支持其他系统吗**
目前脚本只支持 Debian / Ubuntu（apt 系）。Alpine / CentOS 等可以照着 `--dry-run` 生成的配置文件手动落地：装 wireguard、放配置到 `/etc/wireguard/v4exit.conf`、出口机加 NAT 和转发、`wg-quick up v4exit`。

## 安全说明

- 私钥由 `wg genkey` 在本机生成，保存在 `/etc/wireguard/v4exit.key`（权限 600），永不上传、不经过网络，两台机器之间只传公钥。
- 隧道只承载应用机的 IPv4 出站流量；出口机会成为应用机的 v4 出口，请只在你自己信任的机器之间这样组网。
- 出口机上应用机的流量以 NAT 形式出网，目标网站看到的是出口机 IP，出口机的商家 ToS 请自行确认。
